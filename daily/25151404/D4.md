## 实际进展

- 代码标准化（`src/data/fetch.py`）：
  - 新增 `_normalize_symbol` / 重写 `_normalize_symbols`，`fetch_market_data` 与 `fetch_realtime_quotes` 现接受裸 6 位、带 `.SH/.SZ` 后缀（大小写不敏感）、`sh`/`sz` 前缀，统一规范为 `600519.SH` / `000001.SZ`。

- 股票搜索：新增 `search_stock_symbols(query, *, limit=20) -> pd.DataFrame`，返回 `symbol, name, market`；数据源 `ak.stock_info_a_code_name`（东财全市场代码/名称表），只保留沪/深、剔除北交所；去重 + 按 symbol 稳定排序，`limit` 收敛到 [1, 200]，无匹配返回空表（不抛异常），在线列表获取失败抛 `NoDataError`，进程内缓存避免搜索框每次敲键重拉全表。

## 遇到的问题与解决

- 问题：`tests/integration/test_market_service.py` 两个旧用例编码了「裸代码必须拒绝」的旧行为，D4 改为「接受裸代码」后它们失败（全仓 316 passed、2 failed）。
- 解决：组长授权后改为真正非法 `600519.XY` 与合法但缺失的 `600000.SH`，全仓回到 **318 passed**。只动这一个集成测试文件，未改 Service / 页面 / Contract。
- 协助来源：组长 Laurenhuan 授权。

- 问题：真实在线冒烟时，东方财富接口间歇性 `ProxyError`（`push2his.eastmoney.com` 无法连代理）。
- 解决：验证了多源回退链路——日线自动回退腾讯 `stock_zh_a_hist_tx`、实时自动回退新浪，最终数据完整，`df.attrs` 正确记录 `akshare_tencent` / `akshare_sina`。
- 协助来源：多源回退设计（D3 已落地）。

- 问题：`stock_info_a_code_name` 返回的全市场列表含北交所（830000 / 920xxx 等），直接入搜索会混入不支持的代码。
- 解决：`_get_stock_universe` 用 `_symbol_with_exchange_safe` 映射后 `dropna` 剔除北交所，只保留沪 6 / 深 0、3。

- 问题：`git push` 到 gitee 认证失败（Git Credential Manager 缓存了旧 token，报 `Incorrect username or password`）。
- 解决：用一次性带 token 的 URL 推送成功（`d3d39df..fce4045`），未把 token 写入任何文件或 commit；临时 PR 脚本用完即删。

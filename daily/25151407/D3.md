## 遇到的问题与解决

- 问题：Role 2 最初的在线方案容易把 AkShare 与上游供应商混为一谈，而且多股票请求可能把部分返回误判成全部成功。
  解决：要求使用 AkShare 官方公开函数，逐股票核对实际返回集合，只对缺失股票调用备用 Provider；页面同时展示 AkShare 数据来源细分和实际上游 provider。
- 问题：腾讯行情在不同板块存在成交量单位差异，私有端点还增加维护风险。
  解决：删除私有 `newfqkline` 直连，改用 `stock_zh_a_hist_tx`；按市场实际语义修正单位，并用 688 科创板、深市主板和清洗链路回归测试锁定行为。
- 问题：EDA 原页面虽然有统计表和图表，但用户仍不知道结果说明什么。
  解决：将 `build_eda_insights` 通过 Service 接入，并把“分析结论”放在第一个标签页；每条结论同时给出发现、依据、解释和免责声明。
- 问题：多个 PR 在短时间内连续更新，Gitee 页面显示与本地远端引用一度不一致。
  解决：不凭“已合并”口头状态写日报，通过 `git fetch origin`、`git log` 和祖先关系核对；最终确认 `origin/main` 已包含 Role 1 合并提交 `89194c2`。
- 问题：Windows CMD 中仅执行 `cd D:\...` 不会从 C 盘切换到 D 盘，导致 `fatal: not a git repository`。
  解决：统一使用 `cd /d D:\Codex工作空间\stock-analysis-system-role-boundaries` 后再运行 Git 命令。
- 问题：页面虽然已经接入 AkShare，但用户仍只能从 10 只固定 Sample 股票中选择，EDA 和模型也默认使用 2024 年离线区间。
  解决：D4 将在线模式改为允许输入任意合法 A 股代码，并让单股/多股工作区共享代码、日期和数据源；Sample Data 只作为断网时的稳定演示降级。
- 问题：把“最新数据”和“实时快照”混为一谈会使 EDA 与模型输入不成立。
  解决：实时接口只展示当前价格快照；EDA、分类、回归和聚类统一使用 API 获取截至最新交易日的历史日线，因为收益率、均线和时间序列训练都需要多个交易日。
- 问题：监督学习页显示约 45 个“测试样本”，容易被理解成 45 只股票或固定数据量。
  解决：确认分类和回归每次只处理一只股票；45 是 2024 年 242 个交易日经过滚动窗口并按最早 80%/最新 20% 切分后的测试集交易日数量。D4 页面将同时显示输入行数、训练区间、测试区间和测试样本含义。
- 问题：聚类结果只有 Cluster 0/1/2，用户不知道类别含义，同时提出希望调整 `k`。
  解决：先由 Role 5 根据中心点动态生成“相对高收益/高波动/深回撤”等中文画像。当前 P0 Contract 明确固定 `k=3`，可调 `k` 必须先由 Role 1、Role 5、Role 6 完成范围和评估方法 Review，获批前不直接修改。

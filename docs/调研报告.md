# 证券金融数据分析与可视化系统调研报告

> 状态：D1 初稿，后续根据真实数据、算法实验和课程反馈补充。

## 一、调研问题

本项目重点调研四类问题：A 股历史数据如何稳定获取并统一口径；金融时间序列如何避免数据泄漏；三类基础算法如何形成互补分析；课程周期内如何用低成本 Web 框架完成可复现展示。

## 二、数据方案

项目选择 Tushare 作为真实行情候选来源，并定义 Sample Data Fallback。D1 实测账号积分不足，不能稳定获取真实行情，因此没有把联网成功作为系统启动条件。数据层统一处理日期、复权说明、成交量和成交额单位、排序、重复记录及数值冲突；公共 Contract 要求 `symbol + trade_date` 唯一。

该方案的优势是离线测试和课堂演示稳定，限制是 Sample Data 不能代表完整市场分布。后续获得有效数据权限后仍需记录来源、时间范围、复权口径和缺失交易日。

## 三、可视化与应用框架

Streamlit 适合短周期数据项目：Python 代码可直接构建控件、表格和多页面应用，集成成本低。Plotly 提供交互提示、缩放和多序列对比，适合行情、收益率、波动率、回撤、混淆矩阵及 Actual vs Predicted 展示。系统以 Service Layer 隔离页面和业务模块，避免页面直接实现清洗或训练逻辑。

## 四、算法选择

- Decision Tree：完成“下一交易日上涨/非上涨”分类，指标为 Accuracy 和 Confusion Matrix，重点控制标签构造和时间顺序切分。
- Linear Regression：回归下一交易日收益率，指标为 MAE 和 R²，并展示 Actual vs Predicted。
- K-Means：对“每行一只股票”的 Stock Profile 聚类；训练前使用 StandardScaler，输出 Cluster、中心和横向定位。

三种算法分别覆盖分类、回归和无监督学习，适合课程目标。P0 不增加复杂模型，以便把数据口径、泄漏检查、可复现性和结果解释做完整。

## 五、当前结论与待补充

当前结论是“标准数据契约 + Sample Fallback + 三种基础算法 + Streamlit”能够在六天课程周期内形成可验证闭环。后续需要补充真实数据覆盖范围、EDA 发现、模型参数、基线结果、误差分析、聚类解释和页面可用性测试，所有结论以实际实验输出为准。
